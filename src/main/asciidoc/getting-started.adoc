[[prerequisites]]
== Prerequisites

* Docker
* For development: Git, Java 25 and ImageMagick (``magick`` or ``convert``) on the path, for the image variants

[[cloning_the_repository]]
== Cloning the repository

Clone into a folder ``spexipedia`` next to fgv-infra-deploy and fgv-keycloak, as the other Spexipedia repositories:

[source,bash]
----
$ mkdir -p spexipedia && cd spexipedia
$ git clone https://github.com/bloomper/fgv-spexipedia-server
$ git clone https://github.com/bloomper/fgv-spexipedia-deploy
----

[[setup]]
== Setup

[[infrastructure]]
=== Shared infrastructure

Keycloak (realm ``fgv``), Mailpit, Umami and Caddy run in the local stack of
https://github.com/bloomper/fgv-infra-deploy[fgv-infra-deploy], checked out two levels up. Start it once as its README
describes; it creates the Docker network ``fgv-local``, which this repository's ``docker-compose.yaml`` joins.

The media server's nginx configuration is ``media/default.conf.template`` in the sibling ``fgv-spexipedia-deploy``
checkout (or where ``SPEXIPEDIA_DEPLOY`` points).

[[configuration]]
=== Configuration

The secrets are files under ``.docker/secrets``, in git with the placeholder ``CHANGE_ME``. Once fgv-infra-deploy's local
stack runs:

[source,bash]
----
$ scripts/init-secrets.sh          # the database passwords
$ scripts/configure-keycloak.sh    # the admin and service client secrets, and the web's client secret in its .env.local
----

[[running]]
== Running

[source,bash]
----
$ docker compose up -d
----

The API answers on ``https://api.spexipedia.fgv.local.nu:8443`` (through Caddy) and the images on
``http://localhost:8089/media/``. To run the API from the IDE instead, stop ``spexipedia-api`` and start
``SpexipediaApplication`` with the profile ``local``: it listens on port 8088 and uses MySQL on port 3311.

[[sample_data]]
== Sample data

With ``API_IMPORT_SAMPLE_DATA=true`` the API replaces everything with sample data at every start (refused in the
``production`` profile); ``API_SAMPLE_DATA_SIZE`` is ``small`` (about twenty full spex pages) or ``large`` (every spex).

Spexipedia comes first: it is the source of the sample spex, categories and tasks, with fixed ids, which Spexregister
copies from the change feed and the other applications read. Start the applications in this order:

. Spexipedia
. Spexregister, which copies base data from Spexipedia and creates the sample users
. The other applications

Spexipedia gives Spexregister's sample users their roles once they exist, and creates ``author@fgv.nu``:

|===
|User |Roles on fgv-spexipedia

|``admin@fgv.nu`` |USER, AUTHOR, EDITOR, ADMIN
|``editor@fgv.nu`` |USER, AUTHOR, EDITOR
|``author@fgv.nu`` |USER, AUTHOR
|``user@fgv.nu`` |USER
|===

The password is ``SAMPLE_USER_PASSWORD``. Spexregister deletes every Keycloak user when it imports its sample data, so
restart Spexipedia after a later restart of Spexregister.

Credits refer to six spexare that Spexregister's sample data creates with fixed ids (published and unpublished, with and
without nicknames); who played which character comes from Spexregister's sample actors. The first spex page shows photos
from Spexgram's sample data.
